Comment j'ai créé mon premier site avec Claude

📅 Publié le 8 janvier 2026 ⏱️ 8 min de lecture

Aujourd'hui, je veux partager avec vous mon expérience de création de mon premier site web : ce blog que vous lisez actuellement. En partant de zéro absolu en HTML et CSS, j'ai réussi à créer un blog professionnel en une seule session (de deux semaines) avec l'aide de Claude. Voici comment j'ai procédé et ce que j'ai appris.

Le point de départ : une vision claire

J'avais une idée simple : créer un blog appelé "niveau zéro" avec trois sections principales (Code, Sport, Lifestyle). Je ne savais pas coder, mais je savais ce que je voulais. C'est le premier conseil que je peux donner : avoir une vision claire de ce qu'on veut créer.

Au lieu de demander "apprends-moi le HTML", j'ai commencé par dire : "Je veux créer un blog avec un titre et une navigation avec 3 parties". Cette approche orientée projet m'a permis d'apprendre en faisant, pas en théorie.

La méthode qui a fonctionné

1. Commencer simple et construire progressivement

On a commencé par la page la plus basique : un header et une navigation. Pas de fioritures, juste la structure. Puis, étape par étape, on a ajouté :

  • La page Sport avec des articles
  • Une mise en page professionnelle pour les articles
  • Une landing page engageante avec des cartes de catégories
  • Une roadmap interactive
  • Une structure de dossiers professionnelle

Chaque fois que j'ajoute quelque chose, je test et j'essai de commeprendre comment ça marche avant de passer au suivant. Pas de précipitation.

2. Poser les bonnes questions au bon moment

Ne pas hésiter à demander "pourquoi" et "comment" dès qu'on ne comprend pas quelque chose.

Quand j'ai vu `` dans le code, je n'ai pas laissé passer. J'ai demandé ce que c'était. Cette curiosité m'a permis de comprendre les concepts au fur et à mesure plutôt que de copier-coller bêtement du code.

Autres questions que j'ai posées :

  • "C'est quoi `class=` et comment on l'utilise ?"
  • "Comment on lie les pages entre elles ?"
  • "Quelle est la structure professionnelle pour organiser plusieurs pages ?"

3. Choisir l'approche professionnelle dès le début

Quand Claude m'a proposé 3 options pour organiser mon blog (simple, intermédiaire, professionnelle), j'ai choisi l'option 3 : la structure professionnelle avec des dossiers séparés pour les pages, le CSS, et les images.

Pourquoi ? Parce que si je veux être professionnel, autant apprendre les bonnes pratiques dès le début. Oui, c'était un peu plus complexe, mais ça m'a forcé à comprendre les chemins relatifs (`../`) et l'organisation de fichiers.

Ce que j'ai appris concrètement

Concepts HTML/CSS maîtrisés :

  • La structure HTML : header, nav, main, article, section
  • Les classes CSS : comment les créer et les utiliser pour styler des éléments
  • La séparation HTML/CSS : pourquoi c'est mieux d'avoir un fichier CSS séparé
  • Les liens : comment naviguer entre les pages avec des chemins relatifs
  • Le responsive design : le viewport meta tag et pourquoi c'est important
  • L'organisation de fichiers : structure professionnelle avec dossiers pages/, css/, articles/

Compétences pratiques développées :

  • Créer une navigation fonctionnelle
  • Structurer des articles de blog lisibles
  • Organiser un projet web professionnel
  • Comprendre comment lier CSS et HTML
  • Utiliser des classes pour réutiliser des styles

Les erreurs que j'ai faites (et corrigées)

Erreur #1 : Mauvais chemin CSS

Mon premier article ne chargeait pas le CSS. Pourquoi ? Parce que j'avais mis `href="../css/style.css"` alors que mon article était dans `articles/sport/` et nécessitait `href="../../css/style.css"` (deux niveaux au-dessus).

Leçon : Bien comprendre où sont ses fichiers et comment les chemins relatifs fonctionnent.

Erreur #2 : Liens de navigation incorrects

Dans mes articles, les liens de navigation pointaient vers `sport.html` au lieu de `../pages/sport.html`. Résultat : liens cassés.

Leçon : Toujours tester ses liens après avoir créé une nouvelle page.

Comment tirer le maximum de Claude pour apprendre le code

Mes conseils basés sur cette expérience :

  • Avoir un projet concret - Apprendre en construisant quelque chose de réel, pas en faisant des exercices abstraits
  • Commencer simple - Ne pas vouloir tout faire d'un coup. Construire progressivement
  • Demander des explications - Chaque fois qu'on ne comprend pas, demander "pourquoi" et "comment"
  • Choisir l'approche pro - Apprendre les bonnes pratiques dès le début, même si c'est plus dur
  • Tester immédiatement - Ouvrir le fichier HTML dans le navigateur après chaque modification
  • Corriger ses erreurs - Les bugs sont des opportunités d'apprentissage, pas des échecs
  • Documenter son parcours - Écrire ce qu'on apprend (comme cet article !)
  • Être curieux sur les détails - Ne pas laisser passer du code qu'on ne comprend pas

L'approche conversationnelle : un game changer

Ce qui a fait toute la différence, c'est l'approche conversationnelle. Au lieu de regarder des tutoriels vidéo de 3 heures où je ne peux pas poser de questions, j'ai pu :

  • Obtenir des réponses instantanées à mes questions spécifiques
  • Demander des explications sur les parties que je ne comprenais pas
  • Adapter le code à mes besoins exacts
  • Corriger mes erreurs en temps réel
  • Progresser à mon rythme sans frustration

Le résultat : un vrai projet dont je suis fier

En quelques jours, je suis passé de zéro connaissance en code à un blog fonctionnel avec :

  • Une landing page professionnelle
  • Trois sections de contenu
  • Des articles bien structurés et lisibles
  • Une roadmap interactive
  • Une organisation de fichiers professionnelle
  • Un design moderne et responsive

Mais surtout, je comprends maintenant comment tout fonctionne. Je ne me suis pas contenté de copier-coller, j'ai appris les concepts fondamentaux.

La suite de mon parcours

Maintenant que j'ai les bases, mes prochaines étapes sont :

  • Mettre mon blog sur GitHub (versioning et backup)
  • Apprendre le JavaScript pour ajouter de l'interactivité
  • Améliorer le design progressivement
  • Ajouter plus de fonctionnalités (formulaire de contact, recherche, etc.)
  • Continuer à documenter mon apprentissage dans des articles

Le message que je veux faire passer : vous n'avez pas besoin de "savoir coder" pour commencer à créer. Commencez par un projet qui vous passionne, utilisez les outils d'IA comme Claude, posez des questions, et apprenez en faisant.

Le niveau zéro n'est pas un handicap, c'est un point de départ excitant. Chaque concept appris, chaque erreur corrigée, chaque page créée est une victoire. Et croyez-moi, ça va beaucoup plus vite qu'on ne le pense.
