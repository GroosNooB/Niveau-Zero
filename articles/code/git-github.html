L'installation de Git et la liaison avec GitHub

Mon parcours semé d'embûches pour publier mon premier site

📅 Publié le 10 janvier 2026 ⏱️ 8 min de lecture

Objectif : Me créer un GitHub propre, pouvoir le relier en local à mon dossier et automatiser la publication des nouvelles versions.

Croyez-moi, le chemin a été LONG et semé d'erreurs que je n'aurais jamais imaginées avant de commencer. Je vais te raconter toute l'histoire, sans filtre : les galères Git, les conflits qui font peur, les « Everything up-to-date » qui arrivent trop tard, et la joie immense quand enfin le site s'affiche correctement en ligne.

Si tu es toi aussi débutant en code et que tu te sens perdu, cet article est pour toi.

Pourquoi j'ai voulu faire ça en 2026 ?

En janvier 2026, je me suis fixé trois gros objectifs perso :

  • Apprendre à coder (au moins HTML/CSS, et un peu JS plus tard)
  • Se mettre sérieusement au run
  • Avancer sur ma vie (roadmap trimestrielle, économies pour un appart à Paris un jour, etc.)

J'avais envie de documenter tout ça vraiment, pas juste des stories Instagram qui disparaissent.

Du coup l'idée est née : créer un petit blog perso où je raconte mes progrès dans ces trois domaines : Code, Sport, Lifestyle. Objectif ultra-modeste : un site simple, beau, qui charge vite, et qui soit en ligne gratuitement.

GitHub Pages s'est imposé comme la solution parfaite (et gratuite).

Étape 1 : Installer Git... et se prendre un mur direct

J'ai téléchargé Git, j'ouvre VS Code, je tape git init dans le terminal... et là :

git : Le terme «git» n'est pas reconnu comme nom d'applet de commande...

J'ai cru que j'avais raté l'installation. En fait non : PowerShell ne trouvait pas Git dans le PATH.

Solution trouvée grâce à Grok : passer le terminal par défaut sur Git Bash dans VS Code.

Et bim, d'un coup git --version marchait. Petite victoire numéro 1.

Étape 2 : Connecter mon dossier local à GitHub... et se tromper d'URL

J'ai créé mon repo sur GitHub : https://github.com/GroosNooB/Niveau-Zero

J'ai tapé :

git remote add origin https://groosnoob.github.io/Niveau-Zero/

Erreur : repository not found.

Évidemment... c'était l'URL du site publié, pas l'URL du dépôt Git.

La bonne :

git remote add origin https://github.com/GroosNooB/Niveau-Zero.git

(Et oui, j'ai mis groosnoob au lieu de GroosNooB... GitHub est insensible à la casse, mais il me le rappelle à chaque push)

Étape 3 : Le moment le plus dur → les conflits Git

J'avais déjà uploadé quelques fichiers directement sur GitHub (README, index.html, css/style.css, articles...).

Puis j'ai bossé en local... et quand j'ai fait git pull : BOUM.

9 fichiers en conflit :

  • index.html
  • css/style.css
  • tous les articles (roadmap-2026, surf-vie-1, surf-vie-2, apprendre-a-coder-avec-claude-1...)

VS Code ouvrait les fichiers avec des trucs bizarres :

<<<<<<< HEAD
ma version locale
=======
version GitHub
>>>>>>> origin/main

J'ai passé un temps fou à cliquer sur « Accept Current Change » ou « Accept Incoming Change » pour chaque bloc.

Parfois je gardais la version distante (celle déjà en ligne), parfois la mienne. Et à chaque fois : git add le-fichier, puis à la fin git commit pour valider le merge.

C'était long, chiant, frustrant... mais j'ai compris un truc énorme : Git ne veut pas que tu perdes du travail sans le voir. C'est chiant sur le moment, mais c'est une sécurité.

Étape 4 : Le premier vrai push réussi

Après plusieurs git push rejetés (« non-fast-forward », « behind »), j'ai enfin eu :

To https://github.com/GroosNooB/Niveau-Zero.git
fe8e60e..263bdc3 main -> main

Et là... j'ai souri comme un idiot devant mon écran.

Étape 5 : La galère finale → « Pourquoi ça n'a pas changé sur le site ? »

J'ai pushé ma nouvelle charte graphique (nouvelles couleurs, typo, espacements, etc.) → commit 263bdc3.

Sur GitHub, les fichiers étaient bien à jour.

Mais sur https://groosnoob.github.io/Niveau-Zero/ → toujours l'ancienne version.

Cause : le cache du navigateur + le petit délai GitHub Pages.

Solutions qui ont marché :

  • Ctrl + Shift + R (hard refresh)
  • Ouvrir en navigation privée
  • Attendre 2–3 minutes

Et là... enfin... ma nouvelle charte graphique était visible. Soulagement total.

Ce que j'ai appris (et ce que je te conseille si tu débutes)

Les leçons essentielles :

  • Git n'est PAS ton ennemi, c'est juste un outil qui demande de la rigueur
  • Toujours faire git pull avant de commencer à coder
  • Ne pas éditer directement sur GitHub ET en local en même temps (ça crée des conflits)
  • Pour tester localement : utilise Live Server dans VS Code ou python -m http.server → c'est beaucoup plus proche de la réalité
  • Le cache navigateur est ton pire ennemi → hard refresh systématique

Et maintenant ?

Le site est en ligne : https://groosnoob.github.io/Niveau-Zero/

Il est encore très simple, mais c'est mon premier site publié de A à Z.

Je vais continuer à l'alimenter : nouveaux articles surf, code, roadmap trimestrielle, peut-être un peu de JavaScript plus tard.

Si tu lis ça et que tu débutes aussi : Fais-le. Même si c'est moche au début, même si tu galères sur Git, même si tu as 15 conflits. La sensation quand tu vois ton site en ligne pour la première fois... ça vaut tous les « fatal: » du monde.

À très vite pour la suite de l'aventure « Niveau Zéro » !

— François
